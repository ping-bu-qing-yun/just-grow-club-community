# 底部导航正中央恢复「+」作为全局发布入口

需求要求「点加号发布活动（管理者）/ 需求与生活（普通用户）」。我们决定：在底部导航（活动 / 发现 / 需求 / 我的）的正中央恢复一个凸起的「+」按钮，作为唯一的全局发布入口。点击后弹出按角色分化的类型选择面板（action sheet）：管理者可见「活动 / 需求 / 生活」；普通用户可见「需求 / 生活」（无活动项）。

这直接**取代**了 in-flight 任务 `refactor-bottom-nav-tabs`「删除发布按钮」的方向——该任务的「四标签」结构保留，但其「删 +」目标被本决策否决。后续实现时需把该任务的剩余工作收敛为「四标签 + 中央 +」。

## Considered Options

- **页面内分散入口**：活动首页「发布活动」、需求页「发布需求/生活」。与 in-flight 重构「删底部 +」兼容、改动最小，但没有统一的全局发布手势，与用户原话「点加号」的产品意象不符。
- **底部中央「+」+ 角色菜单**：一个入口统领所有发布，菜单按角色变化。符合主流社交 App 心智与用户原话，代价是推翻 in-flight 重构的「删 +」方向，并要做 action sheet 与角色分流。

## Consequences

- `BottomNav` 由 4 项改为 5 槽（左二 + 中央 + + 右二）；中央「+」不是一个 tab，不改变 `activeTab`。
- 需新建发布类型选择面板组件；其菜单项由当前用户角色决定。
- 活动首页内的「发布活动」按钮与需求页 hero「发布需求」按钮：**全部移除**，只留底部中央「+」作为唯一发布入口（已定）。
- 活动首页另有的「发现更多活动」按钮一并移除（用户补充）；保留画像条、精选、给你的见面、需求推荐等其余模块，布局需重排以保持视觉平衡。
- 历史任务 `refactor-bottom-nav-tabs` 的「删除发布按钮」目标已被本 ADR 取代，不再保留任务运行目录。
