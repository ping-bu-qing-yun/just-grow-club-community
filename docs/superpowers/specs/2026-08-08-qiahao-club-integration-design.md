# “恰好关系俱乐部”内容整合设计规格

## 1. 目标

将参考 HTML 中的用户端内容完整整合进现有 React 手机端，保留当前“恰好”应用的字体、品牌红、克制圆角、移动安全区和大图活动卡。整合范围包括“三问入门”“QA问答”“基础资料”“画像生成”四个认识自己模块，以及“活动”“发现”“需求”“我的”四个一级栏目。

本轮目标是内容完整、交互可操作、视觉统一的应用界面。现有登录、活动 API、收藏、报名和发布活动继续工作；新引入的问答、画像、需求和生活动态数据先在浏览器持久化，不扩展后端数据库协议。

## 2. 信息架构

底部导航由五栏调整为四栏：

1. **活动**：用户画像摘要、个性化推荐、成熟活动、预活动和一张需求推荐卡；
2. **发现**：全部活动目录，按全部、低压力、深聊、散步、工作坊、预活动筛选；
3. **需求**：需求广场与生活动态双模式，包含发布需求、需求详情、共鸣、收藏与评论入口；
4. **我的**：身份资料、画像成长、参加记录、需求收藏、动态、消息、安全与设置。

原有居中“发布活动”入口移入活动页右上角和“我的记录”；消息入口移入“我的”，同时保留消息列表页面。原有“心愿”不再占一级导航，活动收藏和需求收藏分别进入“我的记录”。

## 3. 认识自己流程

### 3.1 三问入门

连续展示三个低压力多选问题：最近想解决什么、容易接受哪种见面场景、最大的出门阻力。每题使用无边框分区和可切换选项，不使用 HTML 的小卡片外框。顶部显示“约30秒”和四步进度。

### 3.2 QA问答

包含初级必答三题、中级六题和高级稍后三个层级。初级题为自我探知、生活共识、情感理念；回答支持文本输入，语音按钮提供可操作的录音模拟反馈。支持上一题、下一题、跳过中高级和恢复已答内容。

### 3.3 基础资料

包含头像、昵称、生日、性别、学历和职业。布局采用头像主视觉加无边框字段行，避免多个小表单卡。字段保存在本地，并同步到“我的”页面展示。

### 3.4 画像生成

生成“低压力线下重启型”阶段画像，展示画像完成度、四个核心标签、一句洞察、适合先试和先少推荐。画像是可继续完善的需求快照，不表现为永久性格定义。完成后进入活动主页。

流程进度写入 `localStorage`；首次完成后不强制再次出现，用户可从“我的 > 画像成长”重开或继续完善。

## 4. 四个主栏目内容

### 4.1 活动

顶部为用户问候和画像摘要：“你更适合慢一点认识的场景”。首屏使用一张全宽主推荐图，下面展示成熟活动与预活动大图卡。推荐内容包含周五轻聊天晚餐局、深度对谈夜局、周五散步局等参考 HTML 内容，并保留现有 API 活动列表。需求推荐以大图叙事卡穿插在活动流中。

### 4.2 发现

展示完整活动目录，提供低压力、深聊、散步、工作坊和预活动筛选。卡片沿用现有 `ActivityCard` 的大图比例、日期、地点、人数和费用信息。参考 HTML 中新增的活动内容作为前端扩展目录，点击进入统一活动详情。

### 4.3 需求

顶部为“先说出你想遇见什么”大图/色块 Hero。需求模式展示完整需求卡列表、相似/最新筛选、需求详情、共鸣数、评论数和活动回应；生活模式展示双图生活动态、关系话题、关注、评论和共鸣。发布需求使用一句话引导、示例短句、标签和可选图片预览。

需求卡不使用小边框容器，改为图片占比约 40% 的全宽内容卡；评论与数据放在自然分隔线上。需求收藏写入本地状态并在“我的”中展示。

### 4.4 我的

顶部使用现有头像和品牌渐变封面，增加画像类型与完成度。重点入口为画像成长和需求收藏两张无边框色块。下方包含：参加过活动、活动收藏、需求收藏、我的动态、我的画像、我的消息、编辑资料、帮助客服、安全中心、设置和退出登录。

资料编辑页补齐身高、居住地、家乡、情感状态、照片、标签、关于我和见面偏好。活动记录和消息继续复用现有后端状态。

## 5. 组件与状态边界

- `OnboardingFlow`：四步流程容器与步骤切换；
- `LightQuestionsStep`、`QaCardsStep`、`BasicProfileStep`、`PortraitStep`：各自只处理一个模块；
- `ActivitiesHomePage`：画像摘要与推荐内容；
- `ExplorePage`：完整活动筛选目录；
- `NeedsPage`、`NeedDetailPage`、`CreateNeedPage`：需求与生活内容；
- `ProfilePage`：重构后的我的主页；
- `ClubContext`：问答、画像、需求收藏、动态和入门完成状态；
- `QiahaoContext`：继续负责登录、活动、收藏、报名与消息 API。

新增的 `ClubContext` 使用版本化本地键 `qiahao-club-state-v1`，并提供容错读取；业务组件不直接读写 `localStorage`。

## 6. 视觉规范

- 页面宽度继续以 375-430px 为主，桌面仅居中展示手机画布；
- 主标题 27-31px，分区标题 20-22px，正文 12-14px；
- 使用现有系统中文字体，不引入参考 HTML 的独立字体方案；
- 品牌红用于主动作，绿色用于可信、安全、完成状态，橙色用于画像顾虑和预活动；
- 内容卡以无边框、大图片、阴影和留白建立层级，避免密集描边；
- 常规页面水平边距 18px，模块垂直间距 24-30px，卡片内距 14-18px；
- 卡片圆角维持当前约 8px，不采用参考 HTML 的 16-24px 大胶囊造型；
- 动效只用于步骤切换、选项状态、需求共鸣和页面进入。

## 7. 错误与空状态

- 入门流程允许跳过非必填题，三问至少每题选择一项才能生成画像；
- 本地状态损坏时恢复默认值，不影响活动后端；
- 需求筛选无结果时显示清除筛选操作；
- 图片加载失败时使用品牌柔色背景；
- 发布需求为空时在输入区附近提示；
- 活动 API 失败继续使用现有错误页和重试入口。

## 8. 测试与完成标准

- 组件测试覆盖四步入门流程、进度恢复、画像生成和重新进入；
- 导航测试覆盖活动、发现、需求、我的四栏和子页面返回；
- 需求测试覆盖模式切换、筛选、共鸣、收藏和发布校验；
- 原有登录、活动收藏、报名、发布活动、消息和后端测试继续通过；
- Playwright 在 390px 和桌面手机画布中覆盖：登录、完成入门、浏览四栏、打开需求详情、发布需求、查看我的记录；
- 所有页面无横向溢出，底部导航贴合安全区，大图正常解码；
- `npm test -- --run`、`npm run build` 和 `npm run e2e` 全部通过。
