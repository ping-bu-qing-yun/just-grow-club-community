| 风险等级 | 数量 | 当前状态 |

## STRIDE 重点

| 类别 | 场景 | 当前防线 | 状态 |
| --- | --- | --- | --- |
| S：身份伪造 | 会话令牌泄露或伪造 | 令牌随机生成，数据库仅保存 SHA-256 摘要，Cookie 使用 HttpOnly，写请求有 CSRF 校验 | Medium：生产环境必须使用 HTTPS |
| T：数据篡改 | 客户端伪造作者、内容类型或活动状态 | 服务端从会话取得用户；content_items 与三类子表、标签、评论、收藏通过外键约束 | 已解决本次的孤儿内容风险 |
| R：抵赖 | 运营者下架、改状态后无证据 | 创建、编辑、审核、归档与活动生命周期变化均写 content_audit_events | 已落实；举报处置 API 尚未进入本期范围 |
| I：信息泄露 | 画像中出现生日、城市、关系状态等敏感资料 | user_profiles 将资料可见性与联系方式可见性单独建模；不存储精确住址 | Medium：读取 API 必须按 visibility 过滤字段 |
| D：拒绝服务 | 评论、发布、登录、SSE 被刷 | 数据库索引和连接池已存在 | High：仍需在网关或 Fastify 接入限流、正文频率限制和 SSE 连接上限 |
| E：权限提升 | member/host 调用活动发布或管理接口 | 用户角色为受限枚举；活动创建、生命周期和内容治理均有 operator 服务端校验；画像只允许当前会话用户读写 | 已落实当前接口；未来举报处置仍须复用同一授权层 |

## 高优先级运行环境动作

1. 不要让应用运行时继续使用数据库超级用户。为应用创建只具备目标库最小读写权限的账户，并轮换当前超级用户密码。
2. 生产环境强制 TLS、Secure Cookie，并通过 `QIAHAO_WEB_ORIGIN` / `QIAHAO_CORS_ORIGINS` 只列可信来源；仍需在反向代理或 Fastify 配置登录、发布、评论、反馈和 SSE 的限流。

## 本次落地的安全红线

- 不在仓库、DDL、日志或文档中写入数据库和 Redis 密码。
- 公开内容的关联必须有数据库外键，不能仅靠 content_type 和任意字符串 ID。
- 需求与生活发布即上线不代表免于事后治理；举报、审计、隐藏和归档必须保留证据链。
- 画像位置只存城市和区，不存用户实时位置或精确住址。
- 活动报名、容量校验和群聊创建必须在事务中保持一致。

## 尚未完成的生产安全验收

- 资料读取：private 资料只允许本人读取；members 资料不得返回手机号和联系方式。
- 收藏、共鸣、兴趣信号、反馈已经由服务端验证目标存在和类型正确；继续补充频率限制与滥用监控。
- 举报处置：操作人必须从会话获取，不能由请求体传入；当前只有表结构与审计边界，没有完整处置 API。
- 多图：先完成对象存储签名上传、MIME/大小校验和恶意文件扫描，再写入 content_media.url。
- 管理端：每个状态和生命周期变化都写入 content_audit_events；不要只更新主表。
